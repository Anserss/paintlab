## 0. 一句话

系统让你写到什么程度、写到哪一层：

> **目录只读，用户数据可写，派生数据只能经由业务动作改变。**

所有写操作都走「一个事务 + 一个 Command」：要么整体成功、要么整体不生效，并且可以撤销；
每一次写入都会追加到 ledger（账本），界面上任何显示数值都能回溯到具体账本记录。

---

## 1. 数据分区（3.7.1）

| 分区 | 归属 | 可写性 | 说明 |
|---|---|---|---|
| `catalog` | 系统（随版本发布） | 只读 | 品牌、系列、SKU、色值、规格；版本化，随更新合并 |
| `user` | 用户 | 可写 | 库存条目、分组、工作台、批次、用量记录、设置 |
| `custom` | 用户 | 可写 | 目录里没有的漆，独立命名空间，带 `origin = 'custom'` |
| `derived` | 系统计算 | 不可直接写 | 液位、比例读数、库存总计、低库存状态、色环坐标 |

落地位置：

- `catalog` 是构建产物 `public/catalog/*.json`（`index.json` + 7 个品牌包），随版本发布，不写进用户库。
- `user` / `custom` 在本地数据库：桌面版 `%APPDATA%\PAINTLAB`（IndexedDB，固定 origin `app://paintlab`），
  浏览器版为同源 IndexedDB。**升级换版本不换库**。
- `derived` 不落库，只在读取时由 `src/core/math` 与 selector 现算；不提供任何「直接改派生值」的入口。

## 2. 字段级写入权限（3.7.2）

共 22 个字段组：**15 项可写、7 项只读**。

| 实体.字段 | 可写 | 来源 | 校验 / 备注 |
|---|:---:|---|---|
| `Brand.name / shortName / accentHex` | ✕ | catalog | 只读；用户可覆盖「显示别名」（见下） |
| `Brand.displayAlias` | ✓ | user | ≤ 16 字，仅本地生效 |
| `PaintLine.defaultVolumeMl` | ✕ | catalog | 规格只读；采购时用户可在 0.5–2500 内覆盖 `initialMl` |
| `Paint.code / name / hex / paintClass / category` | ✕ | catalog | 禁止用户改色值，防止显示语义漂移 |
| `Paint.sourceUrl / verifiedAt` | ✕ | catalog | 由维护者写入，用户不可编辑 |
| `CustomPaint.*` | ✓ | custom | 必填品牌名（可自建）、名称、色值、类；hex 必须 `#RRGGBB` |
| `StockItem.volumeMl` | ✓ | user | 限「盘点」入口，`[0, initialMl]`，必须填原因 |
| `StockItem.initialMl` | ✓ | user | 采购时 0.5–2500，1 位小数 |
| `StockItem.state / ratioN` | ✓ | user | 采购时写入；`thinned` 必须给 `ratioN` |
| `StockItem.note` | ✓ | user | ≤ 120 字 |
| `StockItem.groupId` | ✓ | user | 必须存在且 `depth ≤ 3` |
| `Group.name` | ✓ | user | 1–16 字，同层不重名 |
| `Group.parentId` | ✓ | user | 不可成环、不可超 3 层 |
| `Workbench.name` | ✓ | user | 1–16 字，全局不重名 |
| `Workbench.note` | ✓ | user | ≤ 60 字 |
| `Bottle.capacityMl` | ✓ | user | 5–250 整数，且 ≥ `remainingMl` |
| `Bottle.ratioN` | ✓ | user | 稀释 / 调漆时写入，0–10，步进 0.1 |
| `Bottle.name` | ✓ | user | ≤ 16 字 |
| `Bottle.remainingMl / baselineMl` | ✕ | derived + user | 只能通过稀释 / 调漆 / 使用 / 清空改变，禁止表单直改 |
| `UsageRecord / MixRecord` | ✕ | system | 只追加，不可编辑、不可删除（可归档） |
| `Settings.*` | ✓ | user | 白名单枚举（见 §2.2） |
| `CatalogVersion` | ✕ | system | 只读 |

### 2.1 目录字段只读是怎么保证的

以下 5 个字段在界面上**一律渲染为只读文本**（DOM 里不是 `input` / `select` / `textarea`，并标注 `aria-readonly`）：

- `Brand.name / shortName / accentHex`
- `PaintLine.defaultVolumeMl`
- `Paint.code / name / hex / paintClass / category`
- `Paint.sourceUrl / verifiedAt`
- `CatalogVersion`

只读字段共 7 组（上表 ✕ 项）。这不是「先让改再回滚」，而是**根本没有可写控件**：
采购页只能选目录条目，色值来自目录，用户改不了。

需要目录之外的颜色时，请使用 `custom` 命名空间的自定义漆料：
用户自带色值与名称，**不覆盖 catalog**，也不会污染品牌目录。

### 2.2 用户可写字段白名单

| 字段组 | 入口 | 约束 |
|---|---|---|
| `Brand.displayAlias` | 品牌别名 | ≤ 16 字，仅本地 |
| `CustomPaint.*` | 自定义漆料 | hex `#RRGGBB`，品牌可自建 |
| `StockItem.volumeMl` | 盘点 | 必须填原因，写入 ledger |
| `StockItem.initialMl` | 采购 | 0.5–2500，1 位小数 |
| `StockItem.state / ratioN` | 采购 | `thinned` 必须带比例 |
| `StockItem.note` | 采购 / 详情 | ≤ 120 字 |
| `StockItem.groupId` | 移动至… | 分组必须存在且 `depth ≤ 3` |
| `Group.name / parentId` | 分组管理 | 不重名、不成环、≤ 3 层 |
| `Workbench.name / note` | 工作台 | 不重名，note ≤ 60 字 |
| `Bottle.capacityMl / ratioN / name` | 调漆台 / 详情 | 见上表 |
| `Settings.*` | 设置页 | 白名单枚举，改完立即生效 |

### 2.3 派生数据只能经由业务动作改变

- 液位（`Bottle.remainingMl` / `baselineMl`）只能通过**稀释、调漆、工作台用量、盘点、清空**这些业务动作改变，
  每个动作都是「一个事务 + 一个 Command」，可以整体撤销。
- 用量 / 调漆记录（`UsageRecord` / `MixRecord`）**只追加**，不提供编辑与删除；需要隐藏时用归档。
- 库存总计、比例读数、低库存状态、色环坐标都是现算值，任何一次写入后重新计算，不单独存储。

## 3. 配额与上限（3.7.3）

| 项 | 上限 | 达到时 |
|---|---|---|
| 工作台数量 | 5 | 按钮禁用 + 说明文案 |
| 分组层级 | 3 | 禁止新建 / 拖入子级 |
| 同层分组数 | 20（软限） | 提示合并，不阻止 |
| 自定义漆料 | 500 条 | 提示并跳转清理 |
| 单 SKU 库存条目 | 20 份 | 提示同类条目过多 |
| 库存条目总量 | 3000 条 | 提示导出归档，不阻止写入 |
| 撤销深度 | 默认 3，可配 3–20 | 超出即丢弃最旧 |
| 本地存储 | 建议 ≤ 30 MB（不含图片） | 占用 > 80% 显示存储警告 |

撤销深度在设置页「撤销深度」里调整：每次写入都走 Zod 校验并追加 ledger，
超出深度时丢弃最旧的撤销记录（不是丢弃账本）。

## 4. 写路径与校验（实现约定）

1. **一个事务 + 一个 Command**：所有写操作由 store 里的 command 统一提交，失败整体回滚。
2. **Zod 校验**：每次写入前校验字段类型、范围与引用完整性（例如 `groupId` 必须存在、比例 0–10）。
3. **ledger 追加**：每个 Command 记录动作、目标、前后值与时间；界面上的数值可回溯到对应记录。
4. **可撤销**：除设置项（白名单）外，写操作都进撤销栈；设置项改完立即生效并回执，**不进撤销栈**。
5. **导入**：`覆盖 / 合并 / 跳过` 三种模式；覆盖会先清空用户数据表，合并按 id 去重、库存取较大余量。
6. **导出**：全量 `.pigment.json` 与库存 CSV（品牌 / 代号 / 名称 / 色值 / 类 / 剩余 ml / 分组 / 工作台）。

---

## 5. 为什么目录只读

- **防语义漂移**：如果允许改目录里的色值，同一个漆号在不同人的库里会显示成不同颜色，
  社区数据、截图与讨论就对不上了。
- **可核验**：目录条目的 `sourceUrl` / `verifiedAt` 由维护者写入，`hexEstimated` 标记推定色值，
  界面用行内 `≈` 与工具栏摘要如实标注，不谎报「官方色值」。
- **可扩展**：目录外需求走 `custom`：用户自带色值，独立命名空间，不覆盖 catalog。
