## 1. 现状核对：设计前必须接受的 6 条硬约束

这些是从代码读出来的事实，不是推测。任何"重做视觉"的方案必须绕开它们，否则会掉数据或掉测试。

### 1.1 ★ 数据跟着 origin 走，而现在的 origin 会变

- `src/data/db.ts`：数据库名 `pigment-depot`，13 张表，`version(1)` → `version(2)`，v2 升级回调 **清空全部表**。
- `scripts/make-launcher.mjs`：C# 单文件启动器把 `dist` 嵌进 exe，`FindFreePort(8787)` 在 **8787–8846** 之间找第一个空闲端口，然后 `Process.Start(url)` 打开默认浏览器。
- IndexedDB 的作用域 = **scheme + host + port**。今天换一次端口，用户看到的就是一个空库。
- 结论：
  1. 桌面化必须让 origin **固定且永不变化**（`http://tauri.localhost` 或 `app://`）。
  2. 迁移只能走"导出 → 导入"（`设置 → 数据运维 → 导出全量 .pigment.json` 已实现，导入三种模式已实现）。
  3. 浏览器版（保留的启动器）必须**改为固定端口**；端口占用时提示用户关闭旧实例，而不是换端口换库。

### 1.2 数据与目录是两层，更新节奏不同

- 目录：`public/catalog/{gsi,jy,index}.json`，617 条（gsi 448 / jy 169），34 条产品线，`catalogVersion` 记录在 settings。
- 用户数据：stockItems / groups / bottles / workbenches / workbenchItems / mixRecords / usageRecords / ledger / commands / settings。
- 目录随版本发布（`settings.catalogMirror` 目前固定 `bundled`，界面只读）。桌面化后它可以独立更新，用户数据不能。

### 1.3 测试锚点就是设计契约（不能改名）

`tests/unit/features/*` 直接用**中文无障碍名**和 `data-*` 锚点定位。重设计必须逐字保留：

```
按钮名：稀释 / 调漆 / 使用 / 入库 / 开涂 / 清空组分 / 本次不扣减稀释剂 / 确认调整 /
       调整余量 / 加入分组 ⋯ / 新建 / 保存 / 确认删除 / 重置数据 / 重置全部数据 /
       导出全量 .pigment.json / 导出库存 CSV / 入库 (2) / 重试 / 去采购 / 撤销 / 1:1.5
锚点：  data-page="depot|procure|mix|workbench|settings"、data-action="undo|redo|new-workbench|
       return-selected|confirm-return|confirm-zero|submit-workbench|edit-workbench|
       delete-workbench|confirm-delete-workbench|move-menu|remove-selected|record-usage|
       stock-in|coat|use|clear|dilute-commit|blend-commit|blend-equalize|blend-clear|
       skip-thinner|reproduce"、
       data-detail-action="workbench|mix|adjust|delete"（详情抽屉底部 4 个动作）、
       data-slot="breadcrumb|workbench-stats|workbench-placeholder|workbench-form-error"、
       data-mix-panel="stock|bottle|dilute|blend|recents"、data-paint-row / data-depot-row /
       data-paint-detail / data-paint-hex / data-stock-item / data-batch / data-coat-target
```

同时 `data-mix-panel="stock"` 的容器必须继续存在（`mix-aux.test.tsx` 依赖）。**视觉可以全换，语义层不动。**

### 1.4 布局硬编码在尺寸 token 上

`--side-nav: 72`、`--top-bar: 44`、`--row: 72`、`--row-compact: 56`、`--tile-w: 120`、`--tile-h: 148`、`--toolbar-h: 48`。重做时要整体替换这套刻度（§3.4），并且**至少 6 个组件文件**跟着改（Shell / TopBar / SideNav / PaintRow / PaintTile / Toolbar）。

### 1.5 视觉现状（要整建制替换）

| 维度 | 现状 | 问题 |
|---|---|---|
| 主题 | 深色为默认（`tokens.css` 基底即深色，`index.html` 上 `class="dark"`） | 与"纸面加墨"相反；8 小时盯屏也偏暗压抑 |
| 强调色 | `#e8a33d` 工业琥珀 | 与漆料本身的黄/橙撞色，无法表达"当前位置" |
| 圆角/投影 | `--radius-card: 2px`、弹层用 `shadow-panel` | 与"圆角一律 0、无投影"冲突 |
| 字体 | Rajdhani / Noto Sans SC / JetBrains Mono，**均未自托管、未打包**（`package.json` 无 fontsource） | 首次启动会回落系统字体，字宽不一致 |
| 装饰 | 扫描线、网点、警示斜纹（红）、包豪斯三原色 | 与"不编造技术感""红色只给删除"冲突 |
| 动效 | 只有 `duration-hover 120 / panel 180 / liquid 220`，无曲线体系 | 无机械感，也没有减少动效策略（除 base.css 的兜底） |

### 1.6 已被文档承诺、代码未实现的东西（新界面不要假装有）

`SHORTCUT_ROWS` 里写了 `1–5 / Ctrl+K 全局搜索 / Ctrl+A / [ ] 切工作台 / ? 帮助`，代码只实现了 `Ctrl/⌘+Z`、`Ctrl/⌘+Shift+Z`、行内 `Space / Enter`、抽屉 `Esc`。自动快照（`snapshots`）标注 P1 未实现。新界面照旧如实标注，或用 §11 的步骤补齐。

## 2. 桌面化方案

### 2.1 三选一（含"别换壳"的过渡方案）

| | **A. Tauri 2（推荐）** | **B. Electron** | **C. 保留 C# 启动器 + Edge `--app`** |
|---|---|---|---|
| 运行时 | 系统 WebView2（Win10/11 常驻） | 自带 Chromium | 用户默认浏览器 |
| 安装包 | 约 **3–8 MB**（NSIS）+ WebView2 引导器 | 约 **90–160 MB** | 单 exe，约 **1–3 MB** |
| 数据位置 | `%APPDATA%\<identifier>`（WebView2 profile） | `app.getPath('userData')` | 用户浏览器 profile（不可控） |
| origin | 固定（`http://tauri.localhost`） | 固定（自定义协议或 `app://`） | **端口浮动 → 库会丢**（§1.1） |
| IndexedDB 稳定性 | 稳；同 identifier 内持久 | 最稳；版本可控 | 差（用户清理浏览器数据即丢） |
| 原生能力 | dialog / fs / updater / single-instance / window-state 插件齐全 | 更全（托盘、多窗、协议拦截） | 无 |
| 更新 | `tauri-plugin-updater` + minisign 签名 + `latest.json` | `electron-updater`（NSIS） | 手动换 exe |
| 体积代价 | 依赖 WebView2 版本（旧 Win10 需 bootstrapper，约 +120 MB 一次性） | 无依赖 | 无 |
| 构建链 | Rust toolchain（一次性安装，CI 需 20–30 min 首次编译） | Node only | **已有**（csc.exe） |
| 选它的条件 | 默认选它 | 需要托盘/多窗/精确 Chromium 行为、或禁用 WebView2 的企业环境 | 只作过渡，不长期 |

**推荐：A（Tauri 2）。** 理由按权重排序：

1. origin 固定 + profile 目录可预期 = 本地优先应用的生命线（§1.1）。
2. 体积/安装体验对"玩家工具"是硬指标（3–8 MB vs 90 MB+）。
3. 窗口装饰可关（`decorations: false`）+ `data-tauri-drag-region` 拖拽区，正好落地"深色命令栏当标题栏"（skill `cross-platform.md` 的要求）。
4. 插件覆盖本项目全部原生需求：`dialog`（导入/导出）、`fs`（快照/CSV）、`updater`、`single-instance`（避免双开写同一个库）、`window-state`（记住 1280×800 与位置）。

**切到 B 的触发条件（写进 ADR）**：① 需要托盘常驻或 2 个以上窗口；② 用户环境明确禁用 WebView2 且不接受 bootstrapper；③ 发现 WebView2 的 IndexedDB 在睡眠/异常退出后出现丢写。

**C 的定位**：`npm run launcher` 保留为"浏览器版/便携版"，但必须改成固定端口 8787（占用即报错），并在页脚显著提示"数据只存在本浏览器，换浏览器/清缓存即丢；请用桌面版或定期导出"。C 退役条件：Tauri 版发布 + 迁移走通 + 一个版本周期无回退。

### 2.2 打包与构建改动（Tauri）

| 项 | 规格 |
|---|---|
| 前端产物 | 沿用 `dist`（Vite），`base: '/'` 保持默认（Tauri 用 `http://tauri.localhost/`，绝对路径可解析） |
| PWA | **桌面构建关闭** `VitePWA`（`--mode desktop` 时不注册 SW）。理由：SW 在 WebView 里只会造成"更新了但看不到新版"，且和 updater 双通道打架 |
| Service Worker | 浏览器版保留 `autoUpdate`；`/catalog/*.json` 的 `StaleWhileRevalidate` 在桌面版取消（改为本地文件读） |
| 字体 | `@fontsource-variable/saira` + `@fontsource-variable/noto-sans-sc` 自托管，随包发布，附 OFL 许可证文本 |
| 图标 | `build/icon.ico`（已有）→ Tauri 需 `icons/32x32.png … 128x128@2x.png` 与 `.ico`，用 `tauri icon build/icon.ico` 生成 |
| 安装器 | NSIS（`nsis` target），`language: SimpChinese`，`installMode: currentUser`（免管理员） |
| 签名 | Windows Authenticode（`signtool`）。**不签名 = SmartScreen 红屏**，首装转化率归零；MIT 开源不放宽这一条 |
| 资源 | `resources: ["resources/catalog/*"]` 可选（若走"目录包独立更新"，见 §2.5） |
| CSP | 收紧到 `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'`（React/Vite 生产无需 eval） |
| 单实例 | `tauri-plugin-single-instance`，第二次启动时聚焦已有窗口 |
| 窗口状态 | `tauri-plugin-window-state` 保存尺寸/位置；最小尺寸 `minWidth: 1120, minHeight: 720` |
| 标题栏 | `decorations: false` + 自绘 `CommandBar`（§5.1）；**系统窗口按钮保留**（Win 上走 `titleBarOverlay` 等价方案或自绘三键用原生 hit-test），不要自绘一套假按钮 |

### 2.3 数据：Dexie / IndexedDB 的三件必须做的事

1. **申请持久化 + 计量**
   - 启动后调用 `navigator.storage.persist()`；`estimate()` 在 WebView 里可能返回 `quota: 0`，`DataPanel` 已做降级（`source: 'tables'`），保持。
2. **原生快照（把 P1 缺口补上）**
   - 时机：每次写事务成功后 30 s 去抖 + 应用退出前 + **数据库版本升级前强制**。
   - 位置：`%APPDATA%\<identifier>\snapshots\pigment-YYYYMMDD-HHmm.pigment.json`，保留最近 5 份。
   - 复用现成序列化：`exportAll()` 的 `PigmentExport`（`format/exportedAt/catalogVersion/…`）。不需要新格式。
   - 判定"应用退出"：Tauri `RunEvent::ExitRequested` 触发一次同步写。
3. **迁移纪律（最重要的一条）**
   - **永远不要再做"升级即清库"**（v1→v2 那个 `upgrade` 回调只能作为一次性的历史事件存在）。
   - 新版本若必须改结构：`version(3).stores({...}).upgrade(tx => …)` 逐表迁移 + 迁移前先落一份快照 + 迁移失败时回滚到快照并在 UI 顶部挂黄旗提示"数据未迁移，已保留原库与快照"。

### 2.4 文件读写：`saveBlob` 必须换实现

现状 `src/features/settings/download.ts` 用 `a[download]` + `URL.createObjectURL`。在 WebView 壳里这条路径不可靠（可能被静默拦截，或落到系统下载目录且用户找不到）。

规格：

```
平台桥（唯一入口）：window.platform?.saveFile({ name, mime, data }) → Promise<'saved'|'canceled'|'failed'>
                    window.platform?.openFile({ accept }) → Promise<{ name, text } | null>
```

- 桌面：Tauri `dialog.save` + `fs.writeTextFile`（快照写同一套）。
- 浏览器：退回现有 `saveBlob` / `<input type=file>`。
- 导出文件名不变（`pigment-depot-YYYYMMDD.pigment.json`、`pigment-depot-inventory-YYYYMMDD.csv`，带 UTF-8 BOM）。
- 导入仍支持 覆盖 / 合并 / 跳过 三模式与影响说明（文案不动）。

### 2.5 更新策略：三条通道，互不阻塞

| 通道 | 内容 | 机制 | 用户感知 |
|---|---|---|---|
| **应用** | 代码、样式、组件 | Tauri updater：签名清单 `latest.json` + minisign 公钥内置；启动后 3 s 静默检查，有新版在命令栏右侧显示黄点，点开才下载 | 顶多一条提示，不打断操作 |
| **目录** | `public/catalog/*.json` + `catalogVersion` | 二选一：①随应用更新（最省事，推荐 v2.0 先用）；②独立数据包：启动时拉 `catalog/manifest.json`，比对 `catalogVersion` 后下载 zip 到 `%APPDATA%/catalog/`，校验 sha256，原子替换。只买"目录常更新"这一点才做② | 设置页显示"目录 2.0.3 / 617 条" |
| **用户数据** | 用户的库存/批次/工作台 | 永不自动改。只做 快照 + 导出 | "已保存快照 3 份" |

数据库版本与应用版本解耦：`appVersion` 在 `package.json`，`dbVersion` 在 `db.ts`，`catalogVersion` 在 catalog 包。设置页三个读数分开显示（现状 `AboutPanel` 已有 app/catalog 两行，加 db 一行）。

## 3. 变体卡与 token

### 3.1 变体卡（写在交付说明最前面，只在一处设置）

```text
变体：yellow / neutral / standard / grid / standard / calm
页面类型：调漆台 控制台；工作台 控制台（工作看板）；仓库 / 采购 / 设置 阅读
主视觉：配方环（真实体积比的环形配方）、色样带（库存色卡册横切面）、瓶阵（磁贴即瓶位）；
        取用语言：滴管刻度（12 格，沿用瓶身 1/12 吸附）
```

| 维度 | 取值 | 为什么是它（不是别的） |
|---|---|---|
| **强调色** accent | `yellow` `#FFFA00`（墨字压上 16.3:1） | 界面周围全是漆色。"当前位置/可点/提醒"必须是**涂料里不存在的一种黄**：纯饱和柠檬黄在真实漆膜里几乎不可复现，且它是唯一能在 `#161616` 上做到 16.3:1 的高亮。**注意与 §3.6 的"撞色护栏"配套**：强调色只以"带切角的填充块 + 墨字"出现，绝不做裸色块——裸色块是色样的领地 |
| **纸色** paper | `neutral`（paper `#F4F4F2` / panel `#FFFFFF`） | 这是一个**判断颜色**的工具。纸色一旦偏暖（warm）或偏青（cool），用户看色样会系统性误判。宁可少一点氛围，也不许色偏 |
| **切角** cut | `standard`（×1：小件 7 / 按钮 8 / 看板 26 / 画框 52） | 桌面按钮高 40–44：`wide`(×1.6 → 12.8px) 会把 8px 字距挤掉，`tight`(×0.6 → 4.8px) 在 40px 高按钮上几乎看不出"能点"。standard 是唯一在 32–44px 控件上都可读的档 |
| **底纹** ground | `grid`（1px 墨 9%，32px 网格） | 调漆台的网格 = 图纸/刻度纸，与"量具""配方表"同一语义；等高线（contours）更像地形图，属于野外/科考叙事，和配方的格子不对味。网格也最不容易和色样抢注意力（它是正交细线，色样是实心块） |
| **密度** density | `standard`（×1；可选 `紧凑` 0.9375 / `宽松` 1.0625 映射现有 `settings.density`） | 617 条目录 + 三栏工作区确实想更紧，但触控目标不能低于 44（§6.1）。standard 下按钮 44/40、行 68，已经比现状 72 更紧。紧凑档保留给纯键鼠用户 |
| **动效** motion | `calm`（去页面入场，保留回应与进出） | 这是每天开的工具，不是官网。`calm` 保留：擦入 280 mech、行落下 200 snap、液位灌满 450 mech、提示进出；去掉：整页快门、逐行入场、乱码预备。演示模式可临时 `full` |

**不能变（全程强制）**：单一强调色只做填充；切角=可点击、正文直角；红色只给删除；宽体大写英文 + 粗体中文；数字全是真数据；细线分区，无圆角/投影/发光/渐变；动效短硬机械，系统"减少动态"时全关。

### 3.6 撞色护栏（本项目特有，必须写进组件规范）

强调色 `#FFFA00` 和漆料色样同处一屏，必须从**形状**和**语境**上区分：

1. **除了三个例外，黄不出现在任何"没有文字的地方"**：命令栏当前分区块、按钮填充、行左侧的当前位置条。裸的黄方块 = 色样。
2. **色样永远带 ring + 网点底 + 直角**；黄块永远带切角（右下）或与墨字同框。
3. **色样区内部禁黄**：色样带、瓶身、配方环、色环图、色板矩阵里，一律不使用 `--ef-signal`。当前位置在色样区用 **墨底反白标签** 表达（不是黄块）。
4. **红色隔离**：`--ef-danger` 只出现在"删除条目 / 删除分组 / 删除工作台 / 清空数据"的按钮文字与确认按钮上，其余任何告警（库存不足、比例越界、稀释剂缺失）一律 **黄底块 + 墨字** 或 **黄旗提示**。

### 4.2 主视觉与取用语言（配方环 / 色样带 / 瓶阵 / 滴管刻度）

调漆业务里只有四样东西：**色样、配方、漆瓶、滴管**。四者的分工是：

| 业务对象 | 在界面上的角色 | 出现在哪里 |
|---|---|---|
| 色样 | 信息原子（识别一支漆） | 行、磁贴、色样带、详情 |
| 配方 | **主视觉①**：配方环；也是历史记录的骨架 | 调漆台中栏、最近配方 |
| 漆瓶 | **主视觉③**：瓶阵；也是产出胶囊的本体 | 工作台磁贴、调漆台中心 |
| 滴管 | **取用刻度**（见 ④）：把"取多少"变成可拉的刻度，不是装饰 | 取用列表行尾、使用量控件、行"调漆"图标 |

#### ① 配方环 · `RatioRing`（调漆台中栏）

```
                 ╭───────────────╮          ← 外沿 12 格刻度（每 30°，对应 1/12 液位刻度）
             ╱   ▓▓▓▓▓▓░░░░░   ╲
            │   ▓▓▓ 原浆  ░░░  │          ← 弧段按真实体积比：原浆=墨实心，稀释剂=斜线纹
            │   ▓▓         ░░  │
             ╲      [瓶身]     ╱           ← 环内居中：产出瓶（液位=remaining/baseline）
              ╰───────────────╯
                  1 : 2                    ← 环下：等效比例（真值，宽体数字）
```

| 规格 | 值 |
|---|---|
| 外径 / 环宽 | 360 / 30（内径 300）；中栏宽度 <440 时缩到 300/26 |
| 段数 | 稀释模式 2 段（原浆 / 稀释剂）；调漆模式 = 组分 × 2（每组拆原浆与稀释剂），最多 6 段 |
| 段间隙 | 2px 纸色缝（不是圆角） |
| 起弧 | 12 点方向，顺时针；**原浆段永远从 12 点开始**（顺序即配方顺序） |
| 数据 | `dilutionPlan.neatMl : thinnerMl`；调漆用 `plan.parts[]` 的 `neatMl/share` |
| 刻度 | 12 格（与瓶身 1/12 刻度同一套吸附，`quantizeLevel`） |
| 中心 | `BottleView`（§10）或空态短句 |
| 读数 | 环右侧 176 宽竖排：原浆 A / 稀释剂 A×N / 产物 A(1+N) / 等效比例，全部 `--ef-t-field` |
| 空态 | 环退化为 12 个 chip 色刻度 + 中心一句"左侧选好漆料，再点稀释或调漆" |
| 禁止 | 不做分段菜单、不做"当前段黄块"（环是数据不是导航）；环内不放黄 |

#### ② 色样带 · `SwatchStrip`（仓库列表上方，56px 高）

- 内容：当前列表（含筛选）里每一条库存的**真实色样**，等宽分段（每段 `clamp(6px, 100%/n, 40px)`），纵向按明度分两行（上浅下深）。
- 交互：悬停 → 该段上方浮出 `No.024 郡士 C80 · 30.0 ml` 字段；点击 → 滚动并选中对应行；选中行的段用**墨色实心 + 白字编号**标记（不用黄，见 §3.6）。
- 数据：`rows.map(paint.hex)` + `volumeMl`；`hexEstimated` 的条目在段内加一道 45° 细斜线（表示"推定色"）。
- 不编造：空库时不画灰块，改走空状态短句。
- 作用：它是"色卡册"的横切面，同时是滚动位置指示器；替代原本需要另开一个视图才能看到的"全局色感"。

#### ③ 瓶阵 · `BottleRack`（工作台磁贴）

- 磁贴 148×176：顶部 88 高是**瓶身剪影区域**（不是纯色块）：瓶体轮廓 + 内部真实液位 + 刻度，颜色来自 `Paint.hex / Bottle.hex`。
- 底部 88：名称（15/600）、色号（13 宽体）、属性行（11 ink-2）、液位读数（`--ef-t-field`，如 `30.0/60.0 ml`）。
- 一排磁贴读起来像台面上一排瓶：这是工作台自己的物料，不需要装饰线稿。
- 选中：直角内描边 2px `--ef-trace` + 左上角 4px 墨块（不是黄）。

#### ④ 滴管刻度 · `DropperScale`（小件，但它是"取用"的语言）

滴管不做大型主视觉——它是**控件级的刻度语言**，出现在三处：

| 位置 | 表现 | 交互 |
|---|---|---|
| 取用列表每行右端 | 一条 12 段竖刻度（每段 4×2px，间隔 2px），实心段 = `remaining/baseline` 吸附到 1/12 后的格数 | 点第 k 段 → 把该行填成"取用 k/12"，并写入原浆量/取用量输入（0.1 步进取整）；悬停显示 `≈ 7/12 · 17.5 ml` |
| 产出胶囊的"使用量" | 水平 12 格刻度 + 可拖指针 | 拖动一格 = 余量的 1/12（吸附），旁边仍保留 0.1 步进的数字输入做精调 |
| 行动作"调漆"图标 | 1.5px 线性滴管（12×20） | 纯图标，配 `aria-label="调漆"` |

- 为什么用 1/12：瓶身刻度本来就是 12 格（`BOTTLE.ticks = 12`，`quantizeLevel` 按 1/12 吸附），取用量沿用同一套"取大概值"的语言，用户不用在两种精度之间换算。
- 禁止：不做"滴一滴"的装饰动画、不做液体下落的循环动效；刻度必须对应真实余量，空瓶时整条刻度为 chip 色（不画假刻度）。

#### 反模板检查（与最接近的 `templates/console.html` 的 3 处不同）

1. **主视觉不是分段圆盘**：圆盘是"入口菜单"，我们的环是"配方比例的可视化"，段数随组分变化、弧长是真值、不可点击。
2. **保留左侧取料列**：模板说"命令栏是唯一导航、没有左侧列表"；调漆台必须同时看到"取用候选"与"计算结果"，两列共存是有理据的分栏，不是多余的导航。
3. **行是色卡行不是编号记录行**：`编号 │ 日期 │ 名称 │ 计数` 的结构只用在"配方历史 / 操作记录 / 批次列表"上；漆料行是 `色样 │ 三段文案 │ 余量条`，形状由内容决定。

### 6.2 双适用规则（鼠标 + 触屏）

1. **凡是有状态的控件，必须在"非悬停"状态下可辨**：触屏没有 hover，所以 hover-only 的动作（行尾 3 个动作）必须有一条非 hover 的等价路径（行 Sheet）；hover 只做增强。
2. **主要按钮**：桌面静止是墨底，悬停擦黄；触屏（`@media (hover: none)`）静止就是黄底。
3. **命中区**：图标按钮视觉 32，命中 44（透明外扩），相邻目标不重叠；列表行整行可点（复选框行除外，复选框单独 44）。
4. **拖拽**：指针位移 >6px 才起拖（现有 `activationConstraint: 6` 保留），触屏长按 300ms 起拖；拖起后原位置 40% 透明留位；**必须有键盘替代**（右键菜单 / Shift+F10 / 分组菜单里的"移动到"）。
5. **滚动**：内容区内部滚动，shell 不滚；滚动条 8px、直角、`scrollbar-color: var(--ef-rule) transparent`；触屏用惯性滚动（`-webkit-overflow-scrolling`）。
6. **焦点**：Tab 可走遍全部控件；焦点框 2px `currentColor`，切角件内缩 4px；焦点顺序 = 视觉顺序；抽屉/弹层打开时焦点进入并处陷阱，`Esc` 关闭后回到触发元素。
7. **双击/长按**：双击行 = 详情（指针）；触屏长按 = 进入多选（不是菜单）。
8. **缩放**：浏览器缩放 100%–200% 不出现横向滚动；字号 ≥11 的界面文字在 200% 下仍可读。
9. **偏好**：`prefers-reduced-motion: reduce` → 全 0ms；`prefers-contrast: more` → `--ef-rule` 加深到 `--ef-ink-2`、ring 加到 2px。
10. **指针形态**：可点 → `pointer`；可拖 → `grab/grabbing`；禁用 → `not-allowed`；文本区 → `text`。不用"手型"表达非可点元素。

## 7. 右下角操作提示（Toaster）规格

### 7.1 位置与尺寸

```
                                                        ┌──────────────────────────┐
                                                        │▌ 已入库 30.0 ml    撤销 ×│  ← 6px 黄竖条 + 墨底白字
                                                        └────────────────────────╯   ← 右下切角 7px
                                                        ┌──────────────────────────┐
                                                        │▌ 稀释剂不足 …              │
                                                        └──────────────────────────┘
                                                      右侧 24 / 底部 24 / 条间距 12
```

| 项 | 值 |
|---|---|
| 位置 | `right: 24px; bottom: 24px`（**避开 52px 批量条**：有批量条时 `bottom: 52 + 16`） |
| 宽 | 固定 **360**（不随窗口变；<1120 时 320） |
| 样式 | 墨底 `#161616`、白字；左侧 **6px 黄竖条**；右下 7px 切角；**无投影**（用 1px `#00000033` 外描边压边即可） |
| 字号 | 正文 15/600；数字 `--ef-t-field` tabular；动作文字 15/700 黄色下划块（浅色主题下这里是深底，所以允许黄字） |
| 层级 | 最高（`--ef-z-toast: 70`），在弹层之上 |
| 进场 | 从下方 12px 推入 + 淡入，**280 mech**；出场 160 mech（≈进场的 0.57） |
| 减少动效 | 无位移、无淡入（0ms），计时不变 |

### 7.2 停留时长（按类型）

| 类型 | 触发例 | 停留 | 可手动关 | 说明 |
|---|---|---|---|---|
| `note` 信息 | 「已选择 C80，前往调漆台」 | **2800 ms** | 是 | 纯陈述 |
| `ok` 回执（无动作） | 「已导入：新增 12 · 更新 3 · 跳过 0」 | **3200 ms** | 是 | 带数据，给一眼看完的时间 |
| `ok + 撤销` 可撤销回执 | 「已稀释 30.0 ml（1:2）」+ 撤销 | **8000 ms** | 是 | 见 §7.4 |
| `error` 失败 | 「导入失败：文件不是合法 JSON…」 | **6000 ms** | 是 | **同时必须**在表单内留下 inline 错误（提示不是唯一信源） |
| `warn` 需要看一眼 | 「还没有工作台，先去工作台页新建一个」 | **5000 ms** | 是 | 黄旗样式（§7.5），不用红 |

**悬停暂停**（鼠标在整个 Toaster 栈上）

- 进入：栈内**全部**计时冻结（不是只冻结被指的那一条）。
- 离开：从冻结的剩余时间继续（不是重置）。
- 上限：累计悬停 **≤20 s**，超过后恢复倒计时（防止鼠标停在角落导致提示永不消失）。
- 失焦窗口：同样冻结；回到窗口后恢复剩余时间（用户没看到的提示不该算已读）。
- 键盘：焦点进入栈内动作按钮时同样冻结。
- 实现提示：用 `performance.now()` 记 `remaining`，暂停/恢复只改基准时间；不用 `setTimeout` 重排。

### 7.3 堆叠上限与溢出

- **同时最多 3 条**（`MAX_TOASTS` 已是 3，保留）。
- 第 4 条到来：**最旧的一条立即收起**（160 mech），新条在栈底出现（280 mech），其余条不上移动画（避免整列跳动）。
- 同 key 合并：同一 `key`（如 `mix:commit`）在 1.5 s 内重复触发时**不新增**，改为把该条停留时间重置为满值并在右侧显示计数 `×2`。避免连点产生 3 条一样的提示。
- 撤销条被"溢出"挤掉时：**优先保留撤销条**（可撤销的机会比信息更重要），即溢出时先收最旧的非撤销条。
- 队列：超过 3 条的其余条目**丢弃**（不排队），因为 3 条之后用户已经不看了；但 `error` 例外——`error` 永远占一格（挤掉最旧的非 error）。

### 7.4 撤销类提示的保留时长

| 项 | 值 |
|---|---|
| 停留 | **8000 ms**（普通 3 倍），因为要"看完 → 决定 → 移动鼠标点撤销" |
| 剩余时间可视化 | 条内顶部一条 **2px 黄线**从满到空（线性，与计时同步；暂停时同步停） |
| 点击撤销 | 立即执行 `undo()`，该条随即收起（160 mech）+ 新一条 `note`「已撤销：稀释 …」（2800 ms，无动作） |
| 多条可撤销堆叠 | 只保留**最近 1 条**可撤销提示；新的可撤销回执到来时，上一条立即降级为普通 `ok`（去掉撤销按钮、时长重置为 3200 ms）——避免"撤销错的那一条" |
| 窗口失焦 | 冻结（§7.2）；但**失焦超过 5 分钟**视为已放弃：直接收起，不留到下次（避免回到窗口时看到一堆过期提示） |
| 页面切换 | 不收起（撤销是全局的），但若切到别的页面后 8 s 到期照常收起 |

### 7.5 样式与语义（与"红色只给删除"对齐）

| tone | 样式 | 用在哪 |
|---|---|---|
| `note` | 墨底 + 黄竖条 | 导航/选择类告知 |
| `ok` | 墨底 + 黄竖条 + 复选小图标（1.5px 线，不用绿色） | 写入成功 |
| `ok + 撤销` | 同上 + 黄字动作「撤销」+ 2px 剩余线 | 可撤销写入 |
| `warn` | 墨底 + **黄块**里一个「!」+ 黄竖条 | 需要看一眼（缺工作台、低库存、比例钳制） |
| `error` | 墨底 + 黄块「!」+ 墨字（**不用红**） | 失败/阻断。红只属于删除按钮 |

**无障碍**：容器 `role="region" aria-label="操作提示"`，每条 `role="status" aria-live="polite" aria-atomic="true"`；进入不抢焦点；动作按钮可用 Tab 到达（在页面焦点顺序之后）；关闭按钮 `aria-label="关闭提示"`。

**内容规则**：一句话，≤ 28 个汉字 + 一个数字；动词用统一定义（入库 / 调漆 / 开涂 / 稀释 / 使用 / 清空）；不在提示里放两个以上的动作。

## 8. 「调漆后生成漆料瓶」数据流改动点

### 8.1 现状（代码事实）

| 环节 | 现在 |
|---|---|
| 产出命名 | `batchName('稀释' \| '调漆', label, totalMl)` → e.g. `稀释 硝基黑 30.0ml`，**硬截断 16 字**（`name.length <= 16 ? text : text.slice(0,16)`） |

| 产出颜色（调漆） | `hex = mixHex(components…)`（`clear` 权重 ×0.5 的加权平均） |

### 8.2 目标字段与默认值

```ts
// core/model/types.ts · Bottle 增量（全部可选，向后兼容）
seq?: number;          // 序号：调漆1 的 1；一旦发放永不回收
colorHex?: string;     // 自定义色 #RRGGBB；缺省 = #FFFFFF
colorAlpha?: number;   // 0–100 整数，缺省 70
```

| 规则 | 取值 |
|---|---|
| 默认名称 | **`调漆1`、`调漆2`、`调漆3`…**（全角数字不混用；不带空格） |
| 序号范围 | 1–9999；计数来源 `settings['mixSeq']`（integer） |
| 序号分配 | **递增，删除不占号**：计数器只在"生成批次"时 +1，删批次/清空/撤销**都不回退**，因此编号会出现空洞（这是明确接受的行为，写进帮助文案：`编号不回收`） |
| 名称上限 | 16 字（沿用 schema）；重名允许（编号已唯一） |
| 默认颜色 | `colorHex = '#FFFFFF'`，`colorAlpha = 70` → 语义 = **「未定色」**：还没调出颜色的批次 |
| 默认色呈现 | 网点底 + 1px ring + 45° 墨 22% 细斜线 + 文案「未定色」（**不能**只画一块 70% 白：叠在 `#FFFFFF` 板上就是 1.00:1，完全不可见；即使落在纸色 `#F4F4F2` 上也只到 ≈1.03:1） |
| 兼容旧数据 | 读取时派生：`name` 存在即用；`colorHex ?? bottle.hex`；`colorAlpha ?? paintClass 推出的透明度`；`seq ?? 解析 name 尾部数字 ?? 0`（不改库也能显示） |
| 与 `mode` 的关系 | **模式不进名字**：模式用角标 `稀释`/`调漆` 表达，名称只承载序号与用户自定义 |

**序号与撤销的关系（必须写死并文档化）**

- `mixSeq` 递增 **不进入** `Command.forward/inverse`（设置项本来就不进撤销栈）。所以"调漆 → 撤销"之后，下一支仍叫 `调漆N+1`，出现空洞。
- 理由：编号是"发过的票"；回收会导致两支瓶同号，比空洞更糟。
- 若用户强烈要求"连号"，备选方案（不推荐）：撤销时把 `mixSeq` 回退，风险是并发/多窗口下的撞号。

### 8.4 颜色编辑控件（`ColorEditor`）

**入口**：产出胶囊的色块（40×40，右下切角 4px，表示可点）；也在仓库详情抽屉的"混合批次"下提供同名入口。

```
┌───────────────────────────────────┐  320 宽，右下切角 7px，白底 + 1px 墨线，无投影
│ // COLOR          调漆3          │  眉标 + 中文对象名
├───────────────────────────────────┤
│ ┌──────┐  未定色                  │  预览 56×56（网点底 + ring）
│ │      │  HEX   [#FFFFFF]         │  输入 40 高，等宽数字
│ └──────┘  透明度 [ 70 ] ▬▬▬●──   │  数字 40 + 滑块（命中 44）
│                                   │
│ 最近使用                          │
│ ▢ ▢ ▢ ▢ ▢ ▢ ▢ ▢ ▢ ▢ ▢ ▢         │  12 个 28×28 色块（直角，ring）
│                                   │
│ [ 用组分混色 ]                    │  次要按钮：mixHex 算出的建议色
├───────────────────────────────────┤
│ 纸面对比 1.03:1  ⚠ 与纸面几乎无差  │  黄旗，文字读数
│ 墨上对比 1.00:1                   │
│              [ 取消 ] [ 应用 ]    │  应用 = 主要按钮（44）
└───────────────────────────────────┘
```

| 控件 | 规格 |
|---|---|
| HEX 输入 | 40 高，`#` 前缀固定，6 位十六进制，逐字校验；不合法时**不回写**、边框 2px trace、下方黄旗一句「需要 6 位十六进制，例如 #A34F2B」 |
| 透明度 | 数字 0–100（整数）+ 滑块；步进 5；键盘 `↑↓` ±5、`Home/End` 到 0/100 |
| 最近使用色 | 最近 **12** 个（最近在前，去重，含 alpha）；存储 `settings['recentBottleColors']: {hex, alpha}[]`；写入时机 = 点「应用」；点击色块立即套到预览（仍需「应用」提交） |
| 用组分混色 | 用现有 `mixHex(components)` 算建议色（`clear` 权重 0.5 已内建），alpha 取 `min(100, 100 - 稀释程度×?)` —— **不要发明公式**：直接 `alpha = 100`（混色是不透明的），并在按钮下方注明「来自 N 个组分的体积加权，仅作建议」 |
| 预览 | 56×56，**必须**叠网点底板 + 1px ring；`alpha < 100` 时预览块下方一行小字 `70%` |
| 纸面对比读数 | 见 §8.5 |
| 键盘 | `Esc` 取消并回焦到色块；`Enter` 在 HEX 输入内 = 应用；面板打开时 Tab 陷阱 |
| 状态 | 应用后：色块 200 snap 变到新色 + 提示「已更新「调漆3」的颜色」（可撤销） |

**"最近使用色"的数据边界**：它是设置项（不进撤销栈），最多 12 条，跨会话保留，随导出/导入一起走。

### 8.5 与纸色的对比检查（算法与阈值）

```
1) 合成：colorHex 以 alpha 叠在 --ef-panel (#FFFFFF) 上 → c
2) 纸面对比 = contrast(c, --ef-paper #F4F4F2)
3) 墨上对比 = contrast(c, --ef-ink #161616)
4) 深色主题：纸面换成 #191919、墨换成 #EDEDED，重算一遍（同一控件两套主题都成立）
```

| 纸面对比 | 判定 | 界面 |
|---|---|---|
| < 1.15 : 1 | **与纸面几乎无差** | 黄旗 + 强制显示 ring/网点/斜线（任何主题都加） |
| 1.15 – 1.35 : 1 | 偏浅 | 黄旗（轻）："偏浅，建议加 ring 或降低透明度" |
| ≥ 1.35 : 1 | 可辨识 | 正常，无提示 |

| 墨上对比 | 用途 |
|---|---|
| ≥ 4.5 : 1 | 允许在该色块上放墨字（我们的规范是**色样内不放字**，所以仅作记录） |
| < 4.5 : 1 | 记录读数，不阻断 |

参考真值：`#FFFFFF` 对 `#F4F4F2` = **1.10:1**（所以默认 70% 白必然是"几乎无差"档 → 这是"未定色"的视觉依据，不是缺陷）。深色主题下 70% 白叠在 `#191919` 上合成约 `#BABABA`，对比约 **9:1**，正常可见（这也是"浅色必须靠网点/描边兜底、深色天然可见"的原因）。

### 8.6 兼容与迁移

| 场景 | 处理 |
|---|---|
| 旧 `Bottle`（无 seq/colorHex/colorAlpha） | 读时派生默认，不写库；只在用户改名/改色时才落新字段 |
| Dexie 版本 | 新增都是**可选字段且不建索引** → 不需要 `version(3)`；若同时改了索引（例如给 bottles 加 `seq` 索引用于排序）→ 必须 `version(3)` + 快照 + 迁移 |
| 导出/导入 | `PigmentExport` 加 `mixSeq` 与新增字段；导入旧备份：`mixSeq = max(现有 seq) + 1`（或 0） |
| 与 `BOTTLE_HEX_EMPTY` 的关系 | `clearBottle` 仍写 `hex: '#bfbfbf'`（历史语义"空"）；显示层优先 `colorHex`；`colorHex` 缺省时按"未定色"渲染（而不是灰块）——两套并存，语义清楚：`hex` = 来源色事实，`colorHex` = 展示色 |

### 8.7 名称就地编辑

- 触发：点名字（或 `F2`）。输入框宽度 = 文字宽 + 24，高 32，无边框（底线 2px trace），字号 15/600。
- 提交：`Enter` 或失焦；取消：`Esc`（回原值）。
- 校验：1–16 字，trim；空 → 不接受（抖动黄旗 1 次，不落库）；重复 → 允许（编号唯一）。
- 提交后：`renameBottle` → 200 snap 换字 → 提示「已重命名为「XX」」+ 撤销。
- 触屏：点名字进入编辑，键盘弹出，输入框自动滚到可见区域。

## 13. 需要拍板的 5 个问题

1. **强调色是否最终用 `#FFFA00`**：它与真实柠檬黄漆膜几乎同色，虽有 §3.6 的护栏，但"色样区零黄"这条纪律必须长期守住。备选 `lime #B8FF3D`（15.0:1）——更不像漆，但更"赛博"，与"工业纸面"气质有偏差。
2. **左导航彻底取消**：命令栏 5 项横排是桌面惯例 + skill 的控制台约定，但会牺牲"图标 + 竖排字"的辨识度。若用户更认左侧栏，则改为 56px 窄栏（图标 + `//0N`），命令栏只留字标与状态。
3. **`mixSeq` 撤销是否回退**：本规格选"不回收"（空洞可接受）。若产品要连号，需接受并发撞号风险。
4. **目录独立更新（§2.5 通道②）** 是否进 v2.0 范围：不进则目录只能随应用更新，回填 465 条推定色值的节奏会被应用发布拖住。
5. **`clearBottle` 是否算"删除"**：本规格把它排除在红色之外（用斜线纹次要按钮），因为它是可撤销的"倒掉"。若产品认为清空=删除内容，则改为红字按钮 + 二次确认。
