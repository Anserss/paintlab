数据范围与字段级权限 / Data Scope & Field-Level Permissions

系统让你写到什么程度、写到哪一层：目录只读，用户数据可写，派生数据只能经由业务动作改变。所有写操作走「一个事务 + 一个 Command」，可撤销，并可回溯到 ledger。

//01数据分区

对应设计书 3.7.1。分区决定「谁能写」，也决定升级时哪些数据会被版本覆盖。

3.7.1 数据分区
分区归属可写性说明
catalog系统（随版本发布）只读品牌、系列、SKU、色值、规格；版本化，随更新合并
user用户可写库存条目、分组、工作台、批次、用量记录、设置
custom用户可写目录里没有的漆，独立命名空间，带 origin = 'custom'
derived系统计算不可直接写液位、比例读数、库存总计、低库存状态、色环坐标

目录数据落在哪

  • public/catalog/index.json + 7 个品牌包
  • 随版本发布，构建产物，不进用户库
  • 版本号显示在设置页「关于」面板

用户数据落在哪

  • 桌面版：%APPDATA%\PAINTLAB（IndexedDB，固定 origin app://paintlab）
  • 浏览器版：同源 IndexedDB
  • 升级换版本不换库；导出走设置页「数据运维」

//02字段级写入权限

共 22 个字段组：15 项可写、7 项只读。只读字段在界面上不是可写控件——不是「先让改再回滚」。

2.1 目录字段只读是怎么保证的

目录字段（品牌名 / 规格 / 色值 / sourceUrl / verifiedAt / CatalogVersion）在本应用里一律渲染为只读文本： DOM 里不是 input、select 或 textarea，并标注 aria-readonly。 采购页只能选目录条目，色值来自目录，用户改不了。

需要目录之外的颜色，请使用 custom 命名空间的自定义漆料：用户自带色值与名称， 不覆盖 catalog，也不会污染品牌目录。

2.3 派生数据只能经由业务动作改变

液位

  • 只能通过稀释、调漆、工作台用量、盘点、清空改变
  • 每个动作都是「一个事务 + 一个 Command」，可整体撤销

记录与读数

  • 用量 / 调漆记录只追加，不提供编辑与删除（可归档）
  • 总计、比例读数、低库存状态、色环坐标都是现算值

//03配额与上限

配额的作用是「提示与兜底」，不是把用户挡在门外：除硬上限外只提示、不阻止写入。

3.7.3 配额与上限
项上限达到时
工作台数量5按钮禁用 + 说明文案
分组层级3禁止新建 / 拖入子级
同层分组数20（软限）提示合并，不阻止
自定义漆料500 条提示并跳转清理
单 SKU 库存条目20 份提示同类条目过多
库存条目总量3000 条提示导出归档，不阻止写入
撤销深度默认 3，可配 3–20超出即丢弃最旧
本地存储建议 ≤ 30 MB（不含图片）占用 > 80% 显示存储警告

//04写路径与校验

实现约定
约定说明
一个事务 + 一个 Command所有写操作由 store 里的 command 统一提交，失败整体回滚
Zod 校验写入前校验字段类型、范围与引用完整性（如 groupId 必须存在、比例 0–10）
ledger 追加每个 Command 记录动作、目标、前后值与时间；界面数值可回溯到记录
可撤销除设置项外都进撤销栈；设置项改完立即生效并回执，不进撤销栈
导入覆盖 / 合并 / 跳过；覆盖先清空用户数据表，合并按 id 去重、库存取较大余量
导出全量 .pigment.json 与库存 CSV（品牌 / 代号 / 名称 / 色值 / 类 / 剩余 ml / 分组 / 工作台）

//05为什么目录只读

防语义漂移

  • 允许改目录色值，同一个漆号在不同人的库里会显示成不同颜色，社区数据与截图就对不上

可核验

  • sourceUrl / verifiedAt 由维护者写入，hexEstimated 标记推定色值，界面用 ≈ 与工具栏摘要如实标注

可扩展

  • 目录外需求走 custom：用户自带色值，独立命名空间，不覆盖 catalog

可撤销

  • 用户数据的所有写操作都能整体撤销，并留下 ledger 记录
