## 3. 调漆台重做（稀释 / 调漆双模式）

旧模型：一支调漆瓶 + 选容量（15/30/60/100 + 自定义）+ 三模式计算（补满 / 指定原浆 / 反算总量）。

新模型：**两种模式**，都不再让用户选瓶容量。

### 3.1 稀释模式

- **原浆 → 已稀释漆料**：填原浆量 A（正算）或目标总量 V（反算）+ 比例 1:N，
  扣减原浆 A 与稀释剂 A×N，产出体积 A(1+N)、比例 1:N 的批次。
- **已稀释漆料再稀释**：仓库里 `state=thinned` 的条目可直接取用，
  填取用量 M + 目标比例 1:N（N 必须 > 当前 r0）：
  `补加稀释剂 = neat×(N−r0) = M×(N−r0)/(1+r0)`，产物 = M + 补加量。
- 删除了「瓶容量选择」与「补满模式」（补满依赖瓶容量，语义已不存在）。

### 3.2 调漆模式

- 多选组分（原浆 / 已稀释漆料），每组填份量 ml。
- 打开「按目标总容量 V 分摊」时：各组按所填 ml 的比例分摊 V（合计恰好 = V）；
  关闭时：按各组 ml 直接累加。
- 每组按自身稀释比例折算原浆：`neat = ml/(1+r)`；等效比例 = Σ稀释剂 / Σ原浆。
- 库存不足按组分逐个给出「仅剩 X ml，本次需要 Y ml」并阻断提交。

### 3.3 批次与后续动线

- 每次提交生成一支批次（`Bottle.mode = 'dilute' | 'blend'`），调漆台可切换历史批次。
- 批次动作：**入库**（变成仓库条目；比例 0 且非调漆产物记作原浆，其余记作已稀释漆料）、
  **开涂**（送到工作台，多工作台时弹选择）、使用、清空、最近配方复现。

### 3.4 其他流程优化

- 仓库行点「调漆」→ 跳转调漆台并**自动选中该条库存**（只应用一次，不覆盖后手选择）。
- 采购页离开时清空面包屑，修复「顶部栏残留上一页面包屑」。
- 出库/入库回执、撤销标签统一使用新动词（已入库 / 已调漆 / 已开涂）。

## 5. 迁移与回滚

- 数据库 v2 升级是**不可逆的清库**：升级前如需保留旧数据，用设置页「导出全量」备份；
  但旧 SKU 与新目录不同源，导入旧备份会出现解析不到目录的条目，不建议跨代恢复。
- 回滚代码需同时回滚 `docs/seed` 与 `public/catalog`；数据库版本不会自动降级，
  需在 DevTools 删除 `pigment-depot` IndexedDB 后重进。
